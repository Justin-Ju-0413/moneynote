# 深色模式实现说明

> 落地于 2026-09-11（PR #23）。本文记录架构决策与调色板要点，供后续调色/排查对比度问题时参考。

## 核心决策

### 1. 变量重定义，组件零分支

项目全部颜色在第一批重构后已收敛为 Tailwind v4 `@theme` CSS 变量（`bg-bg`、`text-text`、`border-primary-200/30` 等工具类编译后引用 `var(--color-*)`）。因此暗色实现 = 在 `:root[data-theme="dark"]` 重定义变量值，**组件层没有任何 `isDark` 分支**。新增组件只要坚持用语义类，即自动双主题。

### 2. accent / heading 与实底色解耦

一个变量不能同时胜任「按钮实底」和「深底上的文字」：亮色下 `primary-600`（#0c4a94）既做按钮底又做强调文字；暗色下文字需要提亮、实底需要保持对比。为此拆出两个文字专用语义色，承接原 `text-primary-600/700` 的全部 57 处用途：

| 变量 | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `--color-accent` | #0c4a94 | #7baada | 强调文字/链接/hover（原 text-primary-600） |
| `--color-heading` | #0b3d7d | #a8c8e8 | 大标题（原 text-primary-700） |

按钮/chip 实底继续用 `bg-primary-600`（暗色微调为 #115a94，配 `text-bg` 浅字对比不变）。

### 3. 色阶暗色重映射规则

- 浅阶 50–300（背景/边框用途）→ 调暗（#16212c ~ #46617c）
- 亮阶 400–500（状态点/点缀文字）→ 提亮（#6f9cc9 / #5f93c7）
- 700/800（hover/active）→ 暗色下**反转为比 600 更亮**，按压反馈从「变暗」变「变亮」，符合暗色直觉

### 4. 其他语义色

`expense`（支出金额文字）暗色提亮至 #7baada；`income`/`success` 提亮至 #10b981、`danger` 提亮至 #e07070（深底上原值对比度不足 4.5:1）。`code-bg/code-text` 本就是深底浅字，双模式共用。

### 5. 切换机制与防闪烁

- `utils/appearance.ts`：三态 `system | light | dark` 存 localStorage（key `appearance`），`applyAppearance` 写 `html[data-theme]` 并同步 PWA `meta[name=theme-color]`；`watchSystemTheme` 在 system 态监听媒体查询变化。
- `index.html` 内联脚本在首帧前同步设置 `data-theme`，避免暗色用户白闪（FOUC）；逻辑与 appearance.ts 保持一致（修改解析规则时两处同步改）。
- CSS 端同时声明 `color-scheme: dark`，滚动条/表单控件跟随。
- 点阵纹理背景无法在 SVG data-uri 里用变量，用 `--bg-pattern` 变量承载两份 url，body 引用变量。

### 6. recharts 适配

轴刻度 `tick.fill`、折线 `stroke`、tooltip `contentStyle` 全部改为 `var(--color-*)` 引用（SVG attribute 支持 CSS 变量），图表自动跟随主题，无需 JS 感知。

## 已知边界

- 分类色（`--color-cat-*` 与用户自定义分类色）是数据可视化色，双主题共用原值；极暗环境下饱和色作为图标文字可读性可接受，未做暗色映射。
- CategoryIcon 边框用分类色 40% 透明度，暗色下依赖分类色自身亮度，未单独适配。

## 验证方式

Playwright 驱动真实页面（记账产生数据后）截图亮暗两态 × 5 页面 + 桌面布局 + 外观卡交互态人工目检；lint / 单测 / build / E2E 全绿（E2E 依赖文本与 role，不感知颜色）。
