> 起草 2026-09-15 · 用户决策已确认：范围全含（视觉 + 体验 + 基建 + 深水区）· 视觉走「现代亲和风」· 先发 1.5.0 · 暂不做 i18n。

## 子代理协作方式

- 可并行的独立任务（图标替换、多页面精修、测试补齐、C4/C7 攻坚）派发 general-purpose 子代理执行，每个子代理拿到自包含任务书（目标文件 + 验收标准 + 测试要求）。
- 主代理负责：任务拆分、子代理产出的集成审查、跨文件一致性、门禁与 PR/发布。

## 风险与对策

| 风险 | 对策 |
|---|---|
| Token 改动全局涟漪 | R1 先改 token 截图对比核心 6 页，再放行子代理页面精修；dark 块每改必镜像 |
| Dexie v14 迁移 | 严格走既有迁移框架 + 契约单测模式，升级幂等 |
| 虚拟滚动与按日分组冲突 | 分组头扁平化为虚拟列表行，行高定常量 |
| SSE + mock LLM | mock-llm 先行扩展（假流分片），E2E 不依赖真实网络 |
| 包体积 | lucide-react 按需 tree-shake；首屏 gzip 度量门 <180kB 保持 |

## 验收门（每批次）

`npm run lint` + `npm test` + `npm run build` + `npm run test:e2e` 全绿 → PR 合并（squash）→ 删分支 → 批末 release → CHANGELOG + ROADMAP 勾选同步提交。

## 执行顺序

R0（发 1.5.0）→ R1 视觉（1.6.0）→ R2 体验（1.7.0）→ R3 基建（1.8.0）→ R4 深水区（1.9.0）。
R3 的测试基建若提前到位可反哺 R2；时间紧可把 R3.1/R3.2 提到 R2 之前。
